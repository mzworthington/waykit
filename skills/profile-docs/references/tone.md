# Tone dimensions

Set the target for each dimension in the project skill. Do not copy another product's calibration into the kit.

| Dimension | Line | Project records |
| --- | --- | --- |
| Pragmatism vs academicism | Abstract theory to runnable commands | Where this product sits, and why |
| Confidence vs humility | Apology and hedging to dismissal | Direct and objective. Do not call a task easy. Do not apologise for a step |
| Formality vs casualness | Bureaucracy to slang | Professional prose. No corporate jargon. No chat slang |
| Distance vs partnership | Impersonal third party to chumminess | Who the writer is to the reader |

## Sentences

- Procedures: `actor + action + condition + result`. Imperative mood.
- Errors: failure condition, then the flag or command that fixes it. No "Sorry", "Oops", or "Please note".
- Open with the capability and when to use it. No runway ("In this section we will", "Let's dive into").

## Contrast the project must keep

Write one pair per surface the project cares about (feature description, prerequisite, error, procedure, CLI flag, empty state). Flawed line, replacement line, why. Lint the banned words with [profile-prose-lint](../profile-prose-lint/SKILL.md).
